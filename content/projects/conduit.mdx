<CaseStudySection eyebrow="01 / Overview" id="overview" title="Document the system as one connected experience.">
  Conduit is a technical-writing portfolio project centered on a webhook-delivery
  system. The documentation spans developer onboarding, core concepts,
  implementation guidance, operations, administration, security, reference,
  and troubleshooting rather than presenting those topics as isolated samples.

  The portfolio signal is the documentation design: organizing many interacting
  technical concepts into a system readers can enter at the level their task
  requires. The project is not presented as client work, employment, or evidence
  of observed production usage.
</CaseStudySection>

<CaseStudySection eyebrow="02 / Documentation challenge" id="challenge" title="Make a connected system approachable before every concept is known.">
  A webhook-delivery system introduces relationships across organizations,
  applications, environments, permissions, endpoints, subscriptions, events,
  deliveries, and delivery attempts. Payload signing, retries, backoff behavior,
  delivery guarantees, dead-letter queues, and replay add operational and
  security concerns to the same model.

  The documentation challenge was to preserve those relationships without
  requiring readers to understand the complete architecture before they could
  complete a useful task. The resulting structure gives onboarding, concepts,
  procedures, reference, operations, and recovery guidance distinct roles while
  keeping them connected through navigation and cross-references.
</CaseStudySection>

<CaseStudySection eyebrow="05 / Developer onboarding" id="onboarding" title="Move from account context to an inspectable delivery path.">

  for a reader to follow the documented integration path. Examples are provided

  than one developer context.

  claim execution against a production Conduit service.

<CaseStudySection eyebrow="07 / Technical depth" id="technical-depth" title="Use selected explanations to make dense subjects navigable.">
  The documentation addresses technical subjects including webhook delivery,
  subscriptions, delivery attempts, retry policies, backoff behavior, delivery
  guarantees, HMAC-SHA256 payload signing, authentication and permissions,
  dead-letter queues, replay, idempotency, event filtering and transformation,
  data models, schema evolution, high-volume publishing, migration, and
  multi-service architecture.

  Rather than reproduce that complete body of material here, the case study
  selects two explanation patterns: a stable end-to-end delivery model and a
  decision flow that turns a failed delivery into a sequence of checks. These
  demonstrate technical communication choices, not independent verification of
  every described platform capability.
